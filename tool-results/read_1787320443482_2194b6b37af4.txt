   163→   163→- Created src/lib/api-auth.ts with `requireUser()` (returns SessionPayload | null),
   164→   164→  `unauthorized()` (401 JSON), and `badRequest(msg)` (400 JSON) helpers. Reused
   165→   165→  in every protected route.
   166→   166→- Auth routes:
   167→   167→  - src/app/api/auth/signup/route.ts POST: validates name/email/password (400),
   168→   168→    enforces password length >= 6, checks duplicate email (409), hashes with
   169→   169→    `hashPassword`, creates user with `newId()`, sets session cookie, returns
   170→   170→    201 { user: { id, email, displayName } }.
   171→   171→  - src/app/api/auth/login/route.ts POST: validates input, looks up user by email,
   172→   172→    returns 401 'Invalid credentials' if not found or password verify fails,
   173→   173→    sets session cookie on success, returns 200 { user }.
   174→   174→  - src/app/api/auth/logout/route.ts POST: clears session cookie, returns 200 { ok: true }.
   175→   175→  - src/app/api/auth/me/route.ts GET: requires auth (401 unauthenticated), loads
   176→   176→    user + preferences relation, returns 200 { user: { id, email, displayName,
   177→   177→    avatar, onboardingCompleted } } (onboardingCompleted defaults to false when
   178→   178→    no preference row exists).
   179→   179→- Onboarding routes:
   180→   180→  - src/app/api/onboarding/recommendations/route.ts POST: requires auth, accepts
   181→   181→    { genres, languages, viewingTime, viewingDevice }. Loads ALL channels from
   182→   182→    DB, builds system + user prompts, calls `ZAI.create()` then
   183→   183→    `zai.chat.completions.create({ messages, thinking: { type: 'disabled' } })`.
   184→   184→    Strips markdown fences from the LLM reply and parses JSON. Validates the
   185→   185→    returned channelIds against the real catalog and clamps to [4, 8]. On ANY
   186→   186→    failure (LLM throws, parse fails, too few valid ids), falls back to a
   187→   187→    deterministic heuristic that picks: genre+language match -> genre only ->
   188→   188→    language only -> verified -> rest. The outer catch also returns a tiny
   189→   189→    fallback list so the frontend NEVER sees a 500 from this route.
   190→   190→  - src/app/api/onboarding/complete/route.ts POST: requires auth, accepts
   191→   191→    { genres, languages, viewingTime, viewingDevice }, JSON-stringifies the
   192→   192→    arrays per schema convention, `db.userPreference.upsert` by userId,
   193→   193→    sets onboardingCompleted: true, returns 200 { ok: true }.
   194→   194→- Channel & favorites routes:
   195→   195→  - src/app/api/channels/route.ts GET: requires auth, supports ?category,
   196→   196→    ?language, ?q (contains on name), ?limit (default 50, capped at 200).
   197→   197→    Selects only public columns - `streamUrl` is NEVER returned to the client.
   198→   198→  - src/app/api/channels/[id]/route.ts GET: requires auth, returns a single
   199→   199→    channel by id (404 if not found), again strips streamUrl.
   200→   200→  - src/app/api/favorites/route.ts GET + POST: GET returns the user's favorited
   201→   201→    channels joined through the Favorite table (newest first). POST takes
   202→   202→    { channelId }, verifies the channel exists (404), creates a Favorite row;
   203→   203→    catches Prisma P2002 (already favorited) and returns 200 with
   204→   204→    `alreadyFavorited: true` for idempotency. New favorites return 201.
   205→   205→  - src/app/api/favorites/[channelId]/route.ts DELETE: requires auth, uses
   206→   206→    `db.favorite.deleteMany` (idempotent - returns 200 even if the favorite
   207→   207→    didn't exist).
   208→   208→- Code-quality pass:
   209→   209→  - All handlers wrapped in try/catch; errors logged with `console.error`
   210→   210→    tagged with the route path; failures return `{ error: string }` with
   211→   211→    sensible status codes (400/401/404/409/500).
   212→   212→  - Used Next 16 typed route params signature: `{ params }: { params: Promise<{...}> }`
   213→   213→    with `await params`.
   214→   214→  - No `any` types; runtime body fields validated with `typeof` checks before
   215→   215→    use.
   216→   216→  - Imported the `Prisma` namespace from `@prisma/client` (value import, not
   217→   217→    type-only) so `Prisma.PrismaClientKnownRequestError` is available as a
   218→   218→    runtime class for the P2002 instanceof check.
   219→   219→- Verified: `bun run lint` passes clean. `bunx tsc --noEmit` shows zero errors
   220→   220→  in src/ (only pre-existing errors in examples/ and skills/ folders, which

   222→   222→- Verified dev server is still healthy by tailing dev.log (GET / returning 200).
